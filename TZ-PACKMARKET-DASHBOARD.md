# ТЗ: Admin Dashboard Packmarket

**Проект:** Packmarket  
**Ниша:** завод по упаковочным материалам  
**Тип:** аналитический Admin Dashboard (SaaS)  
**Аудитория:** менеджеры / администраторы  
**Язык UI:** русский  

---

## 0. Цель

Собрать одноэкранный (desktop-first) аналитический дашборд с:

1. 4 KPI-карточками и трендами  
2. графиком динамики выручки с переключением «Неделя / Месяц»  
3. таблицей последних 10 заказов с фильтром по статусу  
4. экспортом отфильтрованных данных в CSV (UTF-8 с BOM)  
5. адаптивной вёрсткой с горизонтальным скроллом таблицы на планшетах и мобильных

## 3. Типы данных (обязательные)

```ts
// types/order.ts
export type OrderStatus = 'new' | 'in_progress' | 'done';

export interface Order {
  id: string;           // например "PM-1042"
  clientName: string;
  phone: string;        // "+7 (XXX) XXX-XX-XX"
  service: string;      // услуга / тип упаковки
  amount: number;       // сумма в рублях, целое число
  date: string;         // ISO 8601: "2026-11-18"
  status: OrderStatus;
}

// types/kpi.ts
export interface KpiMetric {
  id: 'revenue' | 'orders' | 'avg_check' | 'new_clients';
  title: string;
  value: number;
  previousValue: number; // для расчёта тренда
  unit: 'rub' | 'count';
}

// types/revenue.ts
export interface RevenuePoint {
  label: string;   // "Пн" | "01.11" и т.п.
  revenue: number;
}

export type ChartPeriod = 'week' | 'month';
```

## 4. UI-блоки (строго по макету логики)

### 4.1. Header

- Слева: название **Packmarket** + подзаголовок «Аналитика заказов»  
- Справа: кнопка **«Экспорт CSV»**  
- Без лишних меню, аватаров, уведомлений  

### 4.2. KPI Grid — 4 карточки

Сетка: `1fr × 4` на desktop (≥1200px), `2×2` на tablet (768–1199), `1×4` на mobile (<768).

| # | id | title | unit |
|---|-----|-------|------|
| 1 | revenue | Выручка за период | rub |
| 2 | orders | Количество заказов | count |
| 3 | avg_check | Средний чек | rub |
| 4 | new_clients | Новые клиенты | count |

**Каждая карточка обязана содержать:**

- заголовок метрики  
- текущее значение (форматированное)  
- тренд: процент изменения vs предыдущий период  
- визуальный индикатор: ▲ рост (зелёный) / ▼ падение (красный) / — без изменений (серый)  
- формула: `((value - previousValue) / previousValue) * 100`, округление до 1 знака после запятой  
- если `previousValue === 0` → показывать `«н/д»` без деления на ноль  

### 4.3. График динамики выручки

- Заголовок: «Динамика выручки»  
- Переключатель периодов: **«Неделя» | «Месяц»** (сегмент-контрол или tabs)  
- При `week` — 7 точек (Пн–Вс или даты)  
- При `month` — 30 точек (или дни текущего месяца из mock)  
- Ось Y: рубли (формат `1.2M` / `120K` / `1 200 ₽` — единообразно)  
- Ось X: подписи периода  
- Tooltip: дата + сумма  
- Высота графика: 280–320px  
- Без анимаций дольше 400ms  

### 4.4. Таблица заказов

Заголовок: «Последние заказы»  
Подзаголовок/счётчик: «Показано N из 10» (после фильтра)

**Колонки (порядок фиксирован):**

| Колонка | Поле | Формат |
|---------|------|--------|
| ID | id | моноширинный / secondary |
| Имя клиента | clientName | текст |
| Телефон | phone | текст |
| Услуга | service | текст |
| Сумма | amount | `12 500 ₽` |
| Дата | date | `ДД.ММ.ГГГГ` |
| Статус | status | badge |

**Фильтр статусов** (chips / tabs над таблицей):

| UI-лейбл | Значение фильтра |
|----------|------------------|
| Все | `all` |
| Новый | `new` |
| В работе | `in_progress` |
| Завершен | `done` |

Поведение:

- По умолчанию: **Все**  
- Фильтр применяется к mock-списку **последних 10 заказов**  
- Пустой результат → строка-плейсхолдер: «Нет заказов с выбранным статусом»  
- Статусы в badge:

| status | Лейбл | Цвет (семантика) |
|--------|-------|------------------|
| new | Новый | синий |
| in_progress | В работе | янтарный / оранжевый |
| done | Завершен | зелёный |

### 4.5. Экспорт CSV

Кнопка в header (и дублировать над таблицей — **не обязательно**, достаточно одной в header).

**Что экспортируется:**

- **Отфильтрованные** строки таблицы (текущий статус-фильтр)  
- Если фильтр «Все» — все 10 заказов  
- Если после фильтра 0 строк — кнопка disabled + title «Нет данных для экспорта»

**Формат файла:**

- Имя: `packmarket-orders-YYYY-MM-DD.csv`  
- Кодировка: **UTF-8 с BOM** (`\uFEFF` в начале файла) — обязательно для Excel  
- Разделитель: `;` (точка с запятой — стандарт для русской Excel-локали)  
- Перенос строки: `\r\n`  

**Заголовки CSV (русский, порядок = колонки таблицы):**

```
ID;Имя клиента;Телефон;Услуга;Сумма;Дата;Статус
```

**Значения:**

- `Сумма` — число без символа валюты (`12500`)  
- `Дата` — `ДД.ММ.ГГГГ`  
- `Статус` — русские лейблы: `Новый` / `В работе` / `Завершен`  
- Поля с `;` или кавычками — экранировать по RFC CSV (`"` → `""`, поле в кавычках)  

**Реализация скачивания:**

```ts
// utils/exportCsv.ts — обязательная сигнатура
export function downloadOrdersCsv(orders: Order[], filename?: string): void
```

Алгоритм:

1. Собрать CSV-строку  
2. Добавить BOM: `'\uFEFF' + csv`  
3. `new Blob([content], { type: 'text/csv;charset=utf-8;' })`  
4. Создать временный `<a download>`, клик, revokeObjectURL

## 7. Адаптивность

| Breakpoint | Поведение |
|------------|-----------|
| ≥1200px | KPI в 1 ряд × 4; таблица без скролла |
| 768–1199px | KPI 2×2; таблица в обёртке с `overflow-x: auto` |
| <768px | KPI столбиком; график на всю ширину; таблица — **горизонтальный скролл** |

**Таблица на mobile/tablet:**

- Обёртка: `.table-scroll { overflow-x: auto; -webkit-overflow-scrolling: touch; }`  
- `min-width` таблицы: **720px** (чтобы колонки не сжимались в кашу)  
- Скроллбар аккуратный (тонкий), без ломания layout страницы  
- Sticky первая колонка (ID) — **опционально**, не блокировать сдачу

## 8. Визуальный стиль (кратко)

- Светлая тема, нейтральный фон (`#F5F7FA` / `#FFFFFF`)  
- Акцент: глубокий синий или графитовый (не purple)  
- Карточки: лёгкая граница + мягкая тень **или** только граница (не оба heavy)  
- Шрифт: Inter допустим для SaaS-дашборда; системный стек — fallback  
- Плотность: компактная admin-density (padding карточек 16–20px)  
- Не использовать emoji в UI

## 9. Состояние и логика (без бэкенда)

В `App` / `DashboardLayout` держать:

```ts
const [period, setPeriod] = useState<ChartPeriod>('week');
const [statusFilter, setStatusFilter] = useState<'all' | OrderStatus>('all');
```

- `filteredOrders = statusFilter === 'all' ? orders : orders.filter(o => o.status === statusFilter)`  
- График читает `period` → выбирает `weekSeries` или `monthSeries`  
- KPI на этом этапе **не** пересчитываются от фильтра таблицы (фильтр влияет только на таблицу и CSV)
